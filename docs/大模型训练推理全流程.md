# TODO: 大模型训练、推理全流程

## 概览

大语言模型可以理解为一个经过大量练习的“文本续写器”：**训练时，通过反复预测下一个 Token 来调整参数；推理时，使用训练好的参数，根据已有内容逐个生成 Token。**

这里的 Token 是模型处理文本的基本单位，可能是一个汉字、几个字、一个单词的一部分，或一个标点，并不总是等于一个字或一个词。

先记住两条主线：

```text
训练：准备文本 → 遮住后续内容，让模型预测 → 对照正确答案计算误差 → 调整参数 → 反复练习
推理：输入问题 → 转成 Token → 模型结合上下文计算 → 预测下一个 Token → 重复，直到回答完成
```

两者的计算过程有重叠，但目的不同：训练要**修改模型参数**，推理通常只使用已有参数，不修改它们。参数可以理解为模型在训练中形成的大量可调整数值。

## 一、训练：模型怎么学会预测？

假设训练文本是“今天下雨了，出门记得带伞”。模型看到前面的“今天下雨了，出门记得带”，需要预测后面的内容。

1. **准备数据**：将大量文本切成 Token，并转成模型可处理的数字编号。
2. **预测答案**：模型根据当前位置之前的内容，给词表中的候选 Token 分别打分。词表就是模型能识别的 Token 清单。（词表就是模型使用的所有 Token 及其对应 ID 的字典，文本拆分成 Token 后，就可以通过词表找到对应 Token ID，不同分词器 Tokenizer的词表可能不同，词表就像一盒积木，不同的token可以组合出大量不同的内容）
3. **计算误差**：把预测结果和文本中实际的下一个 Token 对照，用**损失函数**衡量预测得有多不准。
4. **调整参数**：通过**反向传播**和**优化算法**，根据**误差**调整参数，让类似预测在以后更准确。
5. **重复练习**：在大量样本上反复执行，逐渐学到语言中的关联和规律。

实际预训练通常可以并行计算一段文本中多个位置的预测；“遮住后续内容”指每个位置不能偷看自己要预测的后文，并非一定要逐字运行训练。预训练之后还可能有监督微调、偏好优化等阶段，让模型更适合遵循指令和回答问题。

## 二、推理：模型怎么生成回答？

以下以常见的 **Decoder-only Transformer** 为例。假设用户输入：“今天下雨了，出门记得带”。

```text
输入文本
  ↓
Tokenizer：切分文本并转换为 Token ID
  ↓
Embedding + 位置信息：把 ID 转成向量，让模型区分顺序
  ↓
多层 Transformer：每层结合上下文，再加工信息
  ↓
输出层：给词表中每个候选 Token 打分
  ↓
选择下一个 Token，例如“伞”
  ↓
把新 Token 接到已有内容后面，继续预测，直到结束
```

这个循环叫**自回归生成**：每次根据已有内容预测下一个 Token，生成的结果又成为下一次预测的上下文。下面拆开看每一步。

### 1. Tokenizer：先把文字变成编号

Tokenizer 按模型使用的规则切分文本，再把每个 Token 映射成一个 ID。ID 只是词表中的编号，方便后续查找；它本身不表示这个 Token 的含义。

### 2. Embedding 和位置信息：让模型处理内容与顺序

**Embedding（嵌入）**把 Token ID 转成一组数字，叫作向量。可以把向量想象成一张包含多项特征的数字卡片，供模型继续计算。

模型还需要**位置信息**来区分 Token 的先后顺序，因为“猫追狗”和“狗追猫”用了相同的字，意思却不同。不同模型注入位置信息的方式可能不同。

### 3. 自注意力：模型怎样利用前文？

先看结果：读到“今天下雨了，出门记得带”时，模型会从前文找对预测有帮助的信息。“下雨”可能有帮助，“今天”可能帮助不大。自注意力就是模型计算“当前这一步该多参考前文哪些位置”的过程。

计算时，每个位置都会生成三组数字，叫 Q、K、V。可以先这样记：**Q 表示当前这一步在找什么，K 表示每个位置能提供什么线索，V 表示那个位置带有什么信息。**它们不是人写的标签，而是模型从向量计算出来的数字。

以上面的句子为例，模型要预测“带”后面的内容：

1. 当前的 Q 分别和前文各位置的 K 比较，得到一组分数。分数越高，表示模型这一步越会参考那个位置。比如，可以把 Q 想成“带”后面这一步用于找线索的数字，把“今天”“下雨”“了”“出门”“记得”等位置各自的 K 想成它们提供的线索，再看这些线索与当前 Q 的匹配分数。注意：Q 不是“带”后面的字，K 也不是这些 Token 本身；它们都是模型根据向量计算出来的数字。
2. Softmax 把这些分数换成总和为 1 的权重。例如，“下雨”对应的位置可能权重大一些。
3. 模型按这些权重汇总各位置的 V，形成当前预测要用的上下文信息。

这些步骤在模型内部都是向量计算；“权重大”只表示计算时参考得多，不代表模型像人一样理解了这个词。Decoder 还会限制每个位置只能使用当前及之前的内容，不能偷看后文答案。

### 4. FFN：对每个位置的信息再加工

注意力从上下文中提取信息；**FFN（Feed-Forward Network，前馈网络）**会变换每个位置的向量表示，让其中的信息更适合后续预测。它不直接选出下一个 Token，也不单独决定语法。

注意力和 FFN 会在多个 Transformer 层中重复执行。

### 5. 输出层和 Softmax：从内部表示到候选概率

最后，模型把用于预测的向量通过输出层映射到词表，为每个候选 Token 生成一个原始分数（logit）。**Softmax**可以把这些分数转换为概率分布。

举例来说，模型可能给“伞”较高的概率，也给其他候选分配较低的概率。实际生成不一定每次都选择概率最高的 Token：可以选择最高分，也可以按**概率采样**；温度等设置会影响候选分布和结果的随机性。

#### 采样策略

- **Greedy 贪心策略**：固定选择概率排名第一的字词，全程不存在随机抽取，相同的输入每次回答完全一致。
- **Top-K 采样（带随机）**：第一步筛选概率最高的前 K 个词组成候选池，第二步再在其中随机选词。
- **Top-P 核采样（带随机，行业主流）**：把候选词按概率从高到低排列，依次加入，直到累计概率达到设定阈值（比如 0.9），然后从这组词里抽一个。P 越低，输出越稳定；P 越高，输出越多样。与Top-K 不同的是，Top-K始终选中前K个，Top-P 会根据概率的集中度而变化，模型很确定时，概率比较集中，候选集就比较小；模型不确定时，概率分散，候选集就比较大。
- **Temperature 温度参数**：调节随机强弱，配套 Top-K、Top-P 采样使用。不会新增、删改候选词，只缩放词语之间的概率差距。**低温会放大高概率词优势**，随机性大幅减弱，回答保守规整。**高温抹平概率差距**，冷门词汇更容易被选中，内容发散，创意更强。温度趋近 0 时效果近似贪心策略，但仍有可能不一致。

## 三、KV Cache：为什么生成时不用每次重算全部历史？

回答越长，已有上下文越长。如果每生成一个 Token 都从头计算所有历史位置，会重复做很多工作。

**KV Cache** 在推理时保存各层已经计算过的历史 K 和 V：

- **处理输入阶段（Prefill）**：一次处理输入的 Token，计算并保存它们在各层的 K、V，同时得到第一个待生成 Token 的预测。
- **逐步生成阶段（Decode）**：将新生成的 Token 输入模型，为它计算新的 Q、K、V；用新 Q 参考缓存中的历史 K、V 以及当前位置的信息，并把新的 K、V 加入缓存，再预测下一个 Token。

因此，缓存避免了反复计算历史位置的 K、V；新位置仍需要计算自己的 Q、K、V，也仍需要读取历史缓存进行注意力计算。缓存占用显存，并且通常会随上下文长度增加。

## 为什么 AI 训练要在 GPU 上跑

自回归过程需要大量的向量、矩阵运算，QKV 匹配打分、FFN 特征变换、Softmax 归一化全都是批量并行计算，这类计算天生更适合在GPU上运行，CPU串行处理速度会慢几百上千倍。
