# Agentic RAG：大模型自主决策的 RAG 闭环系统
## 解决问题
- 有些简单问题没必要检索，浪费资源
- 没有纠错和评估机制，无法判断检索内容是否准确、足够
- 复杂问题需要多步检索
- 专业术语、精确实体更适合**关键词搜索**，语义检索容易不准
- 本地知识库没内容，不会主动去网络搜索补充，容易编造答案

## 功能
- 意图识别
- 多跳检索的循环：每检索完一轮，都会判断证据够不够，需不需要进行下一轮检索
- 关键词搜索
- 网络搜索
- 效果评估

## ElasticSearch 全文检索
### 倒排索引
对 text 类型字段进行分词处理，拆解为一个个独立词条，再以「词条」为核心，反向关联所有包含该词条的文档。
用户输入关键词检索时，ES 只需通过词条快速匹配对应的文档，无需全表遍历，就能实现海量文本下毫秒级的全文检索。
在 ES 里分词是很重要的，不同的分词建的索引表都不同。ES 默认的分词器对中文支持不好。需要 **iK 分词器**
